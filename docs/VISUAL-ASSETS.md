# 食物与图标素材

本轮 2026-10-04 由 AI 使用当前内置 imagegen 工具生成食物示意照片，再压缩接入本地项目。没有调用额外付费 API；没有从参考视频提取产品素材。

| 文件 | 对应预设配料 |
| --- | --- |
| r1.jpg | 燕麦片、鸡蛋、香蕉 |
| r2.jpg | 鸡胸肉、杂粮饭、西兰花 |
| r3.jpg | 三文鱼、黄瓜、菠菜、橄榄油 |
| r4.jpg | 虾仁、豆腐、番茄 |
| r5.jpg | 瘦牛肉、西兰花、胡萝卜、牛油果 |
| r6.jpg | 核桃、蓝莓；无酸奶 |
| r7.jpg | 馒头、猪瘦肉、大白菜、豆腐 |

所有照片采用暖白陶器、浅奶油亚麻背景、柔和自然光和略俯拍的日常食物摄影方向；无 UI、正文、数值或标识。输出压缩为 720×540 JPEG，七张共 436,620 字节，作为示意而非精确重量照片。

`src/utils/foodVisuals.ts` 为匹配预设配料的菜谱/可靠整道计划返回对应预设图。自建菜谱可在编辑面板选择自己的照片，优先显示经过校验的本机照片；没有照片、替换后不匹配预设或无法可靠匹配的计划显示统一餐盘/分类图，加载失败也回退。热量与营养仍由原食材数据和克数计算。

自选照片自动等比缩小到最长边不超过 480px；单张压缩后不超过 36 KiB，保存在菜谱的可选 `photo` 字段中，随原有 JSON 备份携带，不依赖临时路径或外部图床。为给饮食记录留出小程序本机存储空间，所有菜谱照片的编码总长限制为 512 KiB。微信端从这些数据生成独立目录中的本地预览文件，旧预览在下一次初始化时清理。没有照片的旧数据和旧备份继续有效。

本轮照片选择测试使用原有 AI 生成的 r2.jpg 作为测试文件，不是用户真实上传的照片。照片编辑交接见 `ROUND7-RECIPE-EDIT-HANDOFF.md`；微信相册、相机、图片方向及重新启动的实际表现仍需开发者工具/真机验收。

常规图标和默认图由 AI 编写 SVG，H5 使用矢量；微信使用同源 PNG，避免依赖 SVG image 的端上支持。导航也提供统一的普通/选中状态。未安装新的图标包或运行时图片服务。
