## 1. 产品定位与边界

帮助用户方便地记录饮食、查看热量与营养摄入、安排饮食计划和维护自己的菜谱。优先保证记录方便、计算口径一致、数据可保留，再完善视觉与操作细节。

- 在现有项目上改进，不另做与实际程序脱节的模板。
- 技术栈经源码核对为 uni-app、Vue 3、TypeScript、Pinia 和本地存储，目标平台为微信小程序，H5用于预览及分层验证。
- 推荐为本地规则计算，不是大模型推荐；不默认增加账号、云同步、后端或图片识别。
- 用户确认优化开始时 GitHub 为最新源码；微信因重名申请过名称变更，旧 Markdown 未及时更新。当前名称统一为“一口一口瘦”。
- 本次用户已授权整理下载包并提交、推送 GitHub；没有授权部署或微信提审，当前改动尚未完成微信真机验收。

## 3. 关键操作与验收标准

### 3.1 记录、日期与计划

- 添加食材后选择实际克数，保存成功后刷新仍保留；修改克数应同步更新该条摄入及汇总。
- 删除记录前有反馈与确认路径；最近操作可撤销。撤销不能覆盖后续新操作，切日期或重开后不能依赖它恢复。
- 昨天和今天的记录、计划独立；历史页有明确提示，支持返回今天。已有历史目标保留；旧数据没有目标时显示缺失，不反推。
- “记已吃”仅记未吃成员，重复点击不重复计入；“全部待吃记已吃”处理当天全部待吃计划，文案与选择范围一致。
- “撤回已吃”扣回精确关联的记录并将计划恢复待吃；“移除计划”只去掉计划，已摄入保留；删除对应记录时，关联计划恢复待吃。
- 一份菜谱在计划中是一行及一个操作单位；两次添加同名菜谱仍是两份。部分已吃时只补记剩余成员。
- 旧数据无法可靠归组或无法确认记录关联时，提示需核对，不按名称猜删、归组或重记。

### 3.2 起始日与自建菜谱

- 首页天数为普通显示文字，只有“调整起始日”触发日期选择。选今天是第1天，选6天前是第7天，取消或保存失败保持原日期。
- 自建菜谱横向点击分类，内容区切换对应食材；可命名、添加、修改克数、移除和保存，关闭未保存草稿时给予确认。
- 手机窄屏下内容不横向溢出，保存入口可达；真实键盘遮挡、滚动和安全区需在微信真机检查。

### 3.3 自定义食材

- 入口为记录页“＋添加”中的“＋添加新食材”，已吃和计划模式均可使用；无搜索结果时可从搜索词继续新增。
- 必填名称、已知分量、对应热量和分类；热量支持千卡/千焦。已知克数须大于0且不超过5000克，允许0热量；名称去除首尾空白后1–50字。
- 示例：150克对应180千卡，换算为120千卡/100克；实际添加75克应计90千卡。753.12千焦/150克得出同样结果。
- 分类为主食、蛋白质、蔬菜、水果、油脂、其他。依据有限名称规则建议，不根据热量推断营养类型；混合或不确定的食品归其他，允许手选。
- 保存后提供参考分量快捷项和实际克数输入；快捷项不是建议摄入量。分类与热量换算不等于自动决定用户该吃多少。
- 蛋白质、碳水、脂肪按输入参考分量填写，选填；校验非负、单项及合计与分量关系。超过合理热量上限提示核对单位。
- 重复名称提示用品牌或做法区分；保存失败不更新内存状态，退出未保存内容先确认。
- 新食材共享给搜索、记录、计划、自建菜谱及同类配料替换，刷新后仍可使用。

## 4. 计算和数据保护要求

- 每100克千卡 = 输入千卡 ÷ 输入克数 ×100；千焦先除以4.184。统一用分量计算，汇总后展示取整。
- 沿用原有基础代谢、活动系数及体重分档缺口估算。根据用户授权的口径核查，取消原周期固定加50千卡及周期专属营养比例，统一碳水48%、蛋白质28%、脂肪24%；周期仅保留一般饮食提示。依据与边界见[第二轮交接](../ROUND2-HANDOFF.md)。
- 原食材库数据不随美化改写，不强行让标签热量等于宏量按4/4/9折算值。这是饮食工具估算，不能描述为医学个体化处方。
- 某营养项含未知值时，该项汇总显示“未完善”；其他完整项照常显示。营养不完整时暂停按营养差额推荐，避免把缺失误当不足。
- 主存储键仍为 `journal-v2`，统一保存按日记录、计划、目标、资料、起始日、菜谱、偏好和可选自定义食材；先持久化成功，再更新页面状态。
- 读取并兼容旧数据，保留旧键与历史小计；用户主动修改记录分量时才重算。没有备份且已被旧版覆盖的历史无法恢复。
- 导出包含自定义食材时使用v3备份封装，无自定义食材时为v2；本版可读v2/v3。存储主键版本与导出封装版本是不同概念。
- 导入先校验并预览，默认合并、本机冲突优先；完整恢复前保留一份导入前副本。存在后续修改时不能用直接撤销覆盖新数据。
- 自定义食材数字编号冲突时自动重编号并同步关联；同独立标识但内容不同则拒绝合并，防止混用。
- 本地存储不提供跨设备自动同步；清缓存或换设备前应保存外部备份。迁移、主存储或副本写入失败均应提示并保留原数据。
