## 数据与计算

- 保留 `daily-record`、`meal-plan`、`user-profile`、`grams-memory`、`custom-recipes`、`hidden-recipes`、`start-date` 的既有格式与键。
- 记录新增可选字段 `planItemId`。旧记录无需迁移即可读取，原 ID、时间与小计保留。
- 跨日覆盖前，旧原始字符串保存在 `daily-record-backup-YYYY-MM-DD` / `meal-plan-backup-YYYY-MM-DD`。这是恢复快照，没有历史日期界面，也不是双向同步。
- 写记录、计划、身体资料时先成功落盘，再更新页面状态；存储失败不会显示成功。无法解析的旧当天快照不被新写入覆盖。
- 旧版已吃计划没有可靠记录关联，不能猜测同名记录。点击时解释限制，需用户在记录列表核对后修改/删除；不会自动删同名条目。
- 记录/计划撤销仅保存本次页面实例最近一次操作，刷新或退出后不保证存在；过日不把旧撤销内容放进新的一天。
- 食谱删除改为隐藏并保留自建源数据；本页支持撤销最近一次。没有新增回收站界面。
- `src/utils/calculator.ts`、`src/static/foods.json`、`src/data/recipes.ts` 没有改动。原有热量与营养小计算法保留。食谱替换复用原自建食谱的食材汇总方式。
- 身体输入校验：身高 100–230cm，体重 25–300kg，年龄 18–100 整数。已有不合法值不清除，但不继续生成参考目标；页面说明沿用女性成人公式。

## 微信开发者工具：一次性验收步骤

1. 在这个项目目录运行 `npm ci`、`npm run build:mp-weixin`（本机已经有本轮产物）。
2. 打开微信开发者工具 → 导入项目 → 目录选择 `dist/build/mp-weixin`。manifest 的 AppID 当前为空；使用你的小程序 AppID。如要反复构建，在 `src/manifest.json` 的 `mp-weixin.appid` 中填写本人 AppID，再构建；不要换成别人的 AppID。
3. 用独立测试项目/测试环境导入。已有设备数据先备份；不要为了排错清空真实线上缓存。确认打开的是本轮产物，而不是旧工程目录。
4. 编译后依次检查四个底部页。记录页：记米饭150g→修改200g→管理删除→撤销；做计划加入鸡蛋50g→记已吃→撤回；添加两条同名食物，确认修改/删除只影响指定一条。
5. 关闭并重新进入，确认记录、计划、资料、自建和替换食谱仍在。测试克数为空/0/小数/超大值、身体数据错误值、食谱取消和删除撤销。
6. 点击“预览”，微信扫码，至少检查一台实际手机：软键盘打开后的确认按钮、底部安全区、日期跨日、长食材名、滚动与弹窗关闭。条件允许分别检查 iOS、Android。跨日可在独立测试环境中准备前一天的 `daily-record` / `meal-plan`，不要改动真实数据。
7. 将失败页面、操作顺序、设备/系统、基础库版本一次反馈。本轮没有授权上传、提交审核或发布，请只做本地编译与预览。
