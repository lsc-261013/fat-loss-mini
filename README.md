# 一口一口瘦

在现有 uni-app 微信小程序上持续打磨的饮食记录工具。技术栈：Vue 3、TypeScript、Pinia、本地存储。推荐使用规则计算，没有大模型调用、账号或云同步。

用户已确认 GitHub 源码是优化开始时的最新版本，微信因名称重复完成了名称调整。当前统一使用“一口一口瘦”，包含基于 `437505f5750e9c0bdac5be42261bca9e83375f4f` 的五轮体验与数据优化。代码同步 GitHub 不代表微信线上版本已更新；本轮没有部署或微信提审。

**[用户需求文档（当前版本）](docs/PRD.md)**：已确认需求、实现状态、验收标准、未解决问题及用户与 AI 的贡献分工。更新日期：2026-09-27。

第三轮按“减少AI模板感”的反馈整理了四页：记录清单优先、已吃/计划切换、食材按需添加、共用摄入概览、食谱列表和按需展开的设置说明。保留第二轮数据与计算规则。

第四轮按用户确认的图实现：独立起始日选择、食谱计划按整道展示和批量操作、自建菜谱横向分类与宽敞编辑区。保留逐配料存储、旧计划兼容和原营养计算。

第五轮增加自定义食材：已知分量/热量换算、分类建议、营养选填，并接通记录、计划、自建菜谱与备份。未知营养不当作0，含自定义食材的备份使用v3封装并继续兼容旧v2。

## 已有功能

- 饮食记录、分量修改、批量删除与撤销。
- 计划管理：多选/全选、批量记已吃、撤回、移除；移除计划保留摄入记录。
- 历史日期查看、补记、修改；每日目标快照，未知旧目标不补算。
- 自建食谱、配料替换和今日计划添加；统一按配料计算营养。
- 食谱计划按整道菜展示与操作；自建菜谱使用横向分类和宽敞编辑面板。
- 自定义食材：按已知克数及千卡/千焦换算，分类可调整，营养可留空；共享用于记录、计划和菜谱。
- 起始日独立年月日选择，首页显示开始记录的第几天。
- 本地备份文件、导入预览、合并或完整恢复、导入前副本及文本备用入口。

## 运行

本次环境 Node 24.15.0 / npm 11.12.1。

```powershell
npm ci
npm run dev -- --host 127.0.0.1
npm run typecheck
npm test
npm run build
npm run build:mp-weixin
```

H5：`http://127.0.0.1:5173`。微信开发者工具导入 `dist/build/mp-weixin`，使用自己的 AppID；源码 `src/manifest.json` 中 AppID 为空。

## 目录

- `src/pages`：首页、记录、食谱、我的。
- `src/components`：食材选择、记录编辑、计划管理、备份操作和热量概览。
- `src/store/journal.ts`：按日数据与统一持久化操作；其他 store 适配首页等页面的今日语义。
- `src/utils`：营养计算、输入/备份校验、旧数据兼容、文件适配。
- `src/types`：本地数据类型；`src/styles`：共享视觉样式。
- `src/data` / `src/static`：预设食谱、原食材数据库和图标。
- `src/store/__tests__` / `src/utils/__tests__`：逻辑回归测试。

## 数据和验证边界

新数据保存在 `journal-v2`。首次读取兼容原当天键及首轮按日备份；旧键保留不清理。历史营养小计保留，只有主动修改分量才重算。清理缓存或换设备前，先把备份保存到应用外。
